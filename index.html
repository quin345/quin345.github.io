Architecture

Two engines: KQL for hot streaming, Lakehouse Delta/Parquet for cold history and ML.

Hot - KQL DB ctrader

Eventstream lands natively. Table tick_data3, views ticks_1m + spread view. Real-time dashboard. Hot cache trimmable to ~90d once silver is trusted.

Cold - Lakehouse

Bronze Parquet (backfill ticks/bars, depth events, snapshots) to Silver Delta (deduped ticks, M1 bars, book, metadata) to Gold (1m features, regimes, corr, events).

Bronze L2 - Cosmos DB

ctrader/market_depth partitioned by /symbolId, Entra-ID auth. One raw JSON doc per depth event. Raw + snapshots both kept.

Collectors and pipelines

tick_data/get_tickdata.py

Subscribes spot for every symbol, pushes minimal {timestamp, Symbol, Bid, Ask} JSON to Event Hub. Auto-reconnect. Key Vault - env - CLI flag precedence.

depth_data/get_domdata.py

Subscribes depth for all symbols (chunked, per-chunk errors), one raw doc per ProtoOADepthEvent to Cosmos DB. Variant get_domdata_eventhub.py fronts planned depth Eventstream.

Scala silver job

scala_job/silver_marketdepth_quotes reconstructs L2 snapshots to silver. sjd1 vendors protobuf client so the Spark Job Definition runs standalone.

Metadata SJD

fetch_asset_metadata pulls assets, classes, swaps, commissions, volume rules to lakehouse JSON, snapshotted weekly for point-in-time correctness.

Mining plan mining first, dashboards second

Handling rules

  1. Raw backfill to Lakehouse bronze, never KQL.
  2. Silver/gold always Delta, partitioned symbol/date.
  3. KQL is serving layer only.
  4. Keep raw depth events and snapshots.
  5. Version metadata weekly.

15-minute order-book features

One row per (symbol, 15-min bar), 22 features + 1 forward label. Features describe bar k-1, label looks one bar ahead.

Spread and book

rel_spread_mean/max, imbalance_ratio_mean, vwap_to_spread_ratio. No raw levels - stackable across assets.

Activity and time
